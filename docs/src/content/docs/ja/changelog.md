## 2026.08.25
バージョン: **1.4.0**

ホスト側のオーバーレイに組み込まれたエディタ向けに、候補パネルをページのどこに配置するかを制御できるようにしました。

新機能:

- **`--flyql-panel-z-index`**（既定 `100`）。パネルの重なり順は固定値だったため、より上に来るオーバーレイを持つホストは `.flyql-panel` に直接ルールを書くしかありませんでした。ドロワーやモーダルは 100 をはるかに超えるのが普通で、エディタは動作しているのにパネルだけが完全に隠れていました。
- **`FlyqlEditor` と `FlyqlColumns` の `panelContainer` プロップ**（既定 `body`、両パッケージ）。セレクタまたは要素を受け取り、`document.body` ではなくそこへパネルを描画して、その要素の重なりコンテキストを継承します。z-index の調整は不要です。解決できない指定は `body` に戻り、パネルを開くたびに再解決するため、エディタより後にマウントされたオーバーレイでも機能します。
- **描画先ノードの `data-flyql-panel` 属性**。外側クリックでオーバーレイを閉じるホストが、内部のクラス名に依存せずパネルを判別できます。`panelContainer` を指定していればパネルはオーバーレイの子孫になるため、その判定自体が不要になります。

既存の利用者に変更はありません。パネルは従来どおり `document.body` に描画され、重なり順も 100 のままです。

## 2026.08.25
バージョン: **1.3.0**

エディタをホスト側のデザインシステムに組み込むためのフック。1 行モード、クリアボタン、これまで固定値だったボックス寸法を追加しました。

新機能:

- **`FlyqlEditor` と `FlyqlColumns` の `multiline` プロップ**（既定 `true`、両パッケージ）。`false` ではフィールドが 1 行のままになります。Shift+Enter は改行を挿入せず、貼り付け・ドロップ・IME から届く改行は空白に置き換えられ、長いクエリは折り返さず横スクロールします。
- **`hasClear` と `clearButtonLabel` プロップ**（既定 `false` と `'Clear'`）。値があるときだけ末尾に現れるクリアボタンです。クリックすると通常の値更新の経路でフィールドが空になり — 候補パネルは閉じ、診断も手で消したときと同じように消えます — フォーカスが入力へ戻ります。
- **新しいテーマ変数** `--flyql-border-radius`、`--flyql-padding-block`、`--flyql-label-font-weight`、`--flyql-border-hover`。角丸、上下パディング、ラベルの太さ、ホバー時の枠線に対応します。既定値は現状のままなので、ホストが設定するまで表示は変わりません。[テーマ](/ja/editor/theming/) を参照してください。

バグ修正:

- **先頭の余白がスクロールで消えなくなりました。** 入力欄の `padding-inline-start` にあり、横スクロールするボックスのパディングはスクロール位置 0 でしか存在しないため、スクロールしたクエリがラベルの下に潜り込んでいました。左右の余白は横スクロールしない `.flyql-<root>__container` が持つようになりました。
- **最大スクロール時にハイライト層がキャレットから 1px ずれなくなりました。** `width: 100%` が `right` オフセットを上書きしており（絶対配置では `width` が `right` に優先します）、2 つのテキスト層のスクロール量が食い違っていました。
- **`Home` と `End` が表示位置も動かします。** どちらも `preventDefault()` の後に選択範囲を設定するため、ブラウザ本来の scroll-into-view が働かず、スクロールするクエリではキャレットが画面外に出てキー操作が無反応に見えていました。

ドキュメント:

- `submit` イベントとキーボード表は Shift+Enter と記載していましたが、コンポーネントは以前から Ctrl/Cmd+Enter で発火します。全 11 言語で修正し、Shift+Enter の実際の動作も併記しました。

`.flyql-<root>__input` のパディングを直接上書きしているホストは確認してください。表示結果は同じですが、左右のパディングはコンテナ側に移りました。

## 2026.08.23
バージョン: **1.2.0**

エディタコンポーネントに、既存のアイコンと並ぶテキストラベルが追加されました。位置はフィールド左側。[エディタコンポーネント](/ja/editor/) を参照してください。

新機能:

- **`FlyqlEditor` と `FlyqlColumns` の `label` プロップ**（Vue・React 両パッケージ）。ラベルはフィールド内、クエリ文字列の前に描画されます。長すぎるラベルは入力欄を圧迫せず、フィールド幅の半分で省略記号に切り詰められます。クリックすると入力にフォーカスが移り、テキストラベルは入力のアクセシブル名になります。Vue では自由な内容を置ける `label` スロットも利用できます。
- **Vue の `icon` がプロップになりました**（従来はスロットのみ）。文字列（テキストとして描画）、コンポーネント、または組み込みグリフを消す `false` を受け取ります。`icon` スロットは引き続きプロップより優先されます。React では既存の `icon` レンダープロップも `false` を受け付けます。

動作の変更:

- **アイコンとラベルは新しい flex プレフィックス要素を共有します。** `.flyql-<root>__icon` は絶対配置ではなくなり `.flyql-<root>__prefix` の中に入りました。入力の左パディングもアイコン用の余白を確保しません。アイコンを自前で配置していたスタイルシートは修正が必要です。`--flyql-*` 変数を差し替えるだけのオーバーライドは影響を受けません。
- **`--flyql-code-font-family` の既定値が実際のフォントスタックになりました** — `ui-monospace, SFMono-Regular, Menlo, Consolas, monospace`。単なる `monospace` はブラウザごとに別のフォントへ解決され（macOS の Chrome では Menlo、Safari では Courier）、アイコンとラベルが揃える基準のメトリクスが変わっていました。以前の動作にするには変数を明示的に設定してください。
- **組み込みの虫眼鏡グリフを viewBox 単位で 1 つ下げました**。リングと柄の全体ではなく、リングが文字に対して中央に来ます。

新しいテーマ変数 — `--flyql-label-color`、`--flyql-line-height`、`--flyql-prefix-gap`、`--flyql-icon-offset`、`--flyql-label-offset` — はラベル色、入力の行ボックス、アイコン・ラベル・文字の間隔、2 つの光学補正を制御します。[テーマ](/ja/editor/theming/) を参照してください。

## 2026.08.14
バージョン: **1.1.1**

バグ修正:

- **PostgreSQL generator における JSON パスの boolean 比較。** JSON パスに対する裸の boolean リテラル（`jsonb_column.enabled = true`）はデフォルトのテキスト比較にフォールスルーし、無効な SQL（`text = boolean`）を生成していました。一方、クォート付きの boolean（`= 'true'`）は `jsonb_typeof = 'string'` でガードされ、JSON の boolean に対して黙って何もマッチしませんでした。裸の boolean は、数値の処理と同様に `jsonb_typeof(...) = 'boolean'` ガードと `::boolean` キャストを生成するようになりました。Go、Python、JavaScript で修正されています。

## 2026.08.12
バージョン: **1.1.0**

カラムの `values` 許可リストが、SQL generator、インメモリ matcher、validator にわたって一貫して — かつ意味のある場所でのみ — 強制されるようになりました。完全なセマンティクスは [値の許可リスト](/ja/syntax/values/#値の許可リスト) を参照してください。

挙動の変更:

- **`in` / `not in` リストは許可リストに対して検証されます。** 許可リスト付きカラムの各リスト要素は SQL 生成時にチェックされ、許可リスト外の要素は黙って 0 行にマッチする代わりに `unknown value` で失敗するようになりました。null 要素とカラム参照は対象外です。従来はタイポを含むリスト要素でも SQL を生成していたクエリは、今後は拒否されます。
- **インメモリ matcher が許可リストを強制します。** カラムが `values` を宣言するスキーマで評価する場合、許可リスト外の `=` / `!=` の値や `in` リスト要素は `unknown value` を送出します（従来は黙って評価され、generator とのパリティが崩れていました）。スキーマなしの評価は変更ありません。
- **新しい validator 診断 `value_not_allowed`。** `diagnose()` は、等値比較の値や in リスト要素がカラムの許可リスト外にある場合、位置情報付きのエラーを発行するようになりました。方言からコアへのスキーマブリッジ（`ToFlyQLSchema` / `toFlyQLSchema`）が `values` を引き継ぐようになったため、ブリッジされたスキーマもこの診断の対象になります。

カラムの強制を無効にするには、スキーマからそのカラムの `values` リストを削除してください。

バグ修正:

- **許可リスト付きカラムで `= null` が動作します。** null はドメイン値ではなく存在述語です: `values` 許可リストを持つカラムに対する `col = null` / `col != null` は、`unknown value` で失敗する代わりに `IS NULL` / `IS NOT NULL` を生成するようになりました。
- **パターンは許可リストに対してチェックされなくなりました。** 許可リスト付きカラムに対する `like` / `ilike` / `~` / `!~` パターンは通常どおり生成されます。従来は許可リストに文字どおり含まれないパターンはすべて拒否され、そのようなカラムでのパターンマッチングが不可能でした。
- **Go の PostgreSQL generator は許可リストチェックの前に RHS のカラム参照を解決します。** 許可リスト付きカラムに対する `col = other_column` は、すべての generator でカラム同士の比較を生成するようになりました。従来は ClickHouse と StarRocks が受け付ける一方で、Go の PostgreSQL generator は `unknown value` で拒否していました。

ドキュメント:

- 新しい [値の許可リスト](/ja/syntax/values/#値の許可リスト) セクションと、三値論理に関する [NOT IN と SQL NULL](/ja/syntax/lists/#not-in-と-sql-null) の注記を全 11 ロケールに追加しました。

## 2026.07.21
バージョン: **1.0.2**

バグ修正:

- **非 ASCII 入力に対する一貫した文字オフセット。** parser は 3 言語すべてで入力を Unicode コードポイント単位でスキャンするようになり（Go は `[]rune`、JavaScript は `Array.from(text)` としてスキャン）、`Range` のオフセットはバイト幅や UTF-16 幅に関係なく 1 文字につき 1 ステップ進みます。従来はキリル文字などのマルチバイト文字やサロゲートペア文字で、Go、JavaScript、Python の各ポート間のオフセットがずれていました。
- **`tokenize()` のコードポイント単位のトークンオフセット。** `tokenize()` はすべての言語で `start` / `end` を Unicode コードポイントオフセットとして報告するようになり、あらゆる入力に対して Python、Go、JavaScript で同一になります。従来、非 ASCII（およびサロゲートペア）文字に対して Go はバイト幅、JavaScript は UTF-16 コードユニット幅のトークンスパンを出力し、隙間のないオフセットという不変条件が崩れていました。
- **有効な PostgreSQL 文字列エスケープ。** PostgreSQL generator は、クォートや改行などのバックスラッシュエスケープを含む値に対してエスケープ文字列リテラル（`E'...'`）を出力するようになりました。プレーンな `'...'` リテラルは `standard_conforming_strings`（デフォルト）の下ではバックスラッシュをリテラルとして扱うため、無効な SQL を生成する可能性がありました。エスケープが不要な値は引き続きプレーンな `'...'` として出力されます。
