## 2026.08.14
संस्करण: **1.1.1**

बग फिक्स:

- **PostgreSQL जनरेटर में JSON पथों पर बूलियन तुलनाएँ।** JSON पथ पर नंगा बूलियन लिटरल (`jsonb_column.enabled = true`) डिफ़ॉल्ट टेक्स्ट तुलना पर गिर जाता था, जिससे अमान्य SQL (`text = boolean`) उत्पन्न होता था, जबकि कोट किया गया बूलियन (`= 'true'`) `jsonb_typeof = 'string'` गार्ड के अधीन था और JSON बूलियन के विरुद्ध चुपचाप कुछ भी मैच नहीं करता था। नंगे बूलियन अब संख्या हैंडलिंग की तरह `::boolean` कास्ट के साथ `jsonb_typeof(...) = 'boolean'` गार्ड उत्पन्न करते हैं — Go, Python, और JavaScript में।

## 2026.08.12
संस्करण: **1.1.0**

कॉलम पर `values` allowlist अब SQL जनरेटर, इन-मेमोरी मैचर, और वैलिडेटर में सुसंगत रूप से — और केवल वहीं जहाँ यह उपयुक्त है — लागू की जाती है। पूर्ण सेमेन्टिक्स के लिए [Values Allowlist](/hi/syntax/values/#values-allowlist) देखें।

व्यवहार परिवर्तन:

- **`in` / `not in` सूचियाँ allowlist के विरुद्ध सत्यापित होती हैं।** allowlist वाले कॉलम पर प्रत्येक सूची तत्व SQL जनरेशन के दौरान जाँचा जाता है; allowlist से बाहर का तत्व अब चुपचाप शून्य पंक्तियाँ मैच करने के बजाय `unknown value` के साथ विफल होता है। Null तत्व और कॉलम संदर्भ छूट प्राप्त हैं। जो क्वेरियाँ पहले टाइपो वाले सूची तत्वों के साथ SQL उत्पन्न करती थीं, वे अब अस्वीकृत होंगी।
- **इन-मेमोरी मैचर allowlist लागू करता है।** जब ऐसे स्कीमा के साथ मूल्यांकन किया जाता है जिसके कॉलम `values` घोषित करते हैं, तो allowlist से बाहर का `=` / `!=` मान या `in`-सूची तत्व `unknown value` उठाता है (पहले यह चुपचाप मूल्यांकित हो जाता था, जो जनरेटर के विपरीत समता तोड़ता था)। स्कीमा-रहित मूल्यांकन अपरिवर्तित है।
- **नया वैलिडेटर डायग्नोस्टिक `value_not_allowed`।** `diagnose()` अब स्थिति-सहित त्रुटि उत्सर्जित करता है जब कोई समानता मान या in-सूची तत्व कॉलम की allowlist से बाहर होता है। डायलेक्ट-से-कोर स्कीमा ब्रिज (`ToFlyQLSchema` / `toFlyQLSchema`) अब `values` साथ ले जाते हैं, इसलिए ब्रिज किए गए स्कीमा भी इस डायग्नोस्टिक में भाग लेते हैं।

किसी कॉलम के लिए प्रवर्तन से बाहर निकलने हेतु, स्कीमा से उसकी `values` सूची हटा दें।

बग फिक्स:

- **`= null` allowlist वाले कॉलम पर काम करता है।** Null एक उपस्थिति प्रेडिकेट है, डोमेन मान नहीं: `values` allowlist वाले कॉलम पर `col = null` / `col != null` अब `unknown value` के साथ विफल होने के बजाय `IS NULL` / `IS NOT NULL` उत्पन्न करते हैं।
- **पैटर्न अब allowlist के विरुद्ध नहीं जाँचे जाते।** allowlist वाले कॉलम पर `like` / `ilike` / `~` / `!~` पैटर्न सामान्य रूप से जनरेट होते हैं; पहले कोई भी पैटर्न जो शाब्दिक रूप से allowlist में मौजूद नहीं था, अस्वीकृत हो जाता था, जिससे ऐसे कॉलम पर पैटर्न मैचिंग असंभव थी।
- **Go PostgreSQL जनरेटर allowlist जाँच से पहले RHS कॉलम संदर्भ हल करता है।** allowlist वाले कॉलम पर `col = other_column` अब सभी जनरेटर पर कॉलम-से-कॉलम तुलना उत्पन्न करता है; पहले Go PostgreSQL जनरेटर इसे `unknown value` के साथ अस्वीकार करता था जबकि ClickHouse और StarRocks इसे स्वीकार करते थे।

दस्तावेज़ीकरण:

- नया [Values Allowlist](/hi/syntax/values/#values-allowlist) अनुभाग और त्रि-मूल्य तर्क पर एक [NOT IN और SQL NULL](/hi/syntax/lists/#not-in-और-sql-null) नोट, सभी 11 लोकेल में।

## 2026.07.21
संस्करण: **1.0.2**

बग फिक्स:

- **गैर-ASCII इनपुट के लिए सुसंगत कैरेक्टर ऑफ़सेट।** पार्सर अब तीनों भाषाओं में इनपुट को Unicode कोड पॉइंट के अनुसार स्कैन करता है (Go `[]rune` के रूप में, JavaScript `Array.from(text)` के रूप में), इसलिए `Range` ऑफ़सेट बाइट या UTF-16 चौड़ाई की परवाह किए बिना प्रति कैरेक्टर एक कदम आगे बढ़ते हैं। पहले सिरिलिक और अन्य मल्टी-बाइट/एस्ट्रल कैरेक्टर Go, JavaScript, और Python पोर्ट के बीच ऑफ़सेट को असंगत कर देते थे।
- **`tokenize()` में कोड-पॉइंट टोकन ऑफ़सेट।** `tokenize()` अब हर भाषा में `start`/`end` को Unicode कोड-पॉइंट ऑफ़सेट के रूप में रिपोर्ट करता है, जो सभी इनपुट के लिए Python, Go, और JavaScript में समान है। पहले गैर-ASCII (और एस्ट्रल) कैरेक्टर के लिए Go बाइट-चौड़ाई वाले टोकन स्पैन उत्सर्जित करता था और JavaScript UTF-16-कोड-यूनिट स्पैन, जिससे गैप-रहित ऑफ़सेट इनवैरिएंट टूट जाता था।
- **मान्य PostgreSQL स्ट्रिंग एस्केपिंग।** PostgreSQL जनरेटर अब उन मानों के लिए एस्केप-स्ट्रिंग लिटरल (`E'...'`) उत्सर्जित करता है जिनमें उद्धरण या न्यूलाइन जैसे बैकस्लैश एस्केप होते हैं। सादा `'...'` लिटरल `standard_conforming_strings` (डिफ़ॉल्ट) के तहत बैकस्लैश को शाब्दिक रूप से मानता है, जिससे अमान्य SQL उत्पन्न हो सकता था; जिन मानों को एस्केपिंग की आवश्यकता नहीं है वे अभी भी सादे `'...'` के रूप में रेंडर होते हैं।
